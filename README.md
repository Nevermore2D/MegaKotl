# MegaKotl

Приложение для построения функций по узлам, численного интегрирования и сравнения способов вычисления. Все методы работают с одним набором узлов и одним графиком; тип функции и метод интегрирования выбираются независимо.

## Запуск

Требуются JDK 21 и установленный Gradle. Из корня проекта:

```bash
gradle run
```

Запуск тестов:

```bash
gradle test
```

## 1. Построение функции

Для узлов `(x₀, y₀), ..., (xₘ, yₘ)` доступны четыре способа построения кривой и отдельный режим ввода формулы. Узлы сортируются по `x`; для построения по узлам нужны как минимум две точки с различными абсциссами.

### Полином Лагранжа

Интерполяционный многочлен проходит через **все** заданные узлы. Реализация использует базис Лагранжа:

$$
L(x)=\sum_{i=0}^{m}y_i\ell_i(x),\qquad
\ell_i(x)=\prod_{\substack{j=0\\j\ne i}}^{m}\frac{x-x_j}{x_i-x_j}.
$$

Для вычисления значения в точке `x` программа последовательно строит каждое произведение `ℓᵢ(x)` и суммирует вклады `yᵢℓᵢ(x)`. Повторяющиеся `xᵢ` недопустимы: возникает деление на ноль. На одно вычисление функции требуется `O(m²)` операций. При большом числе узлов и неудачном их расположении интерполяционный полином может сильно осциллировать между узлами.

**Реализация:** `features/polynomials/LagrangePolynomial.kt`.

### Полином Ньютона

Строит тот же интерполяционный полином, но в форме разделённых разностей:

$$
P(x)=c_0+c_1(x-x_0)+c_2(x-x_0)(x-x_1)+\dots.
$$

Коэффициенты вычисляются из таблицы разделённых разностей:

$$
f[x_i,\ldots,x_{i+k}]
=\frac{f[x_{i+1},\ldots,x_{i+k}]-f[x_i,\ldots,x_{i+k-1}]}{x_{i+k}-x_i}.
$$

В коде таблица хранится в одном массиве и заполняется в обратном порядке, чтобы не перезаписывать ещё нужные значения. Подготовка коэффициентов занимает `O(m²)`, а вычисление полинома — `O(m)` благодаря вложенной схеме (аналог схемы Горнера):

```text
result = c[m]
for i = m-1 ... 0:
    result = result * (x - x[i]) + c[i]
```

Для одних и тех же корректных узлов Лагранж и Ньютон математически дают один полином; результаты в `Double` могут немного различаться из-за округлений.

**Реализация:** `features/polynomials/NewtonPolynomial.kt`.

### Тригонометрическая аппроксимация методом наименьших квадратов

Подбирается тригонометрический полином с периодом `2π`:

$$
T(x)=c_0+\sum_{k=1}^{r}\left(a_k\cos(kx)+b_k\sin(kx)\right).
$$

В отличие от полиномов Лагранжа и Ньютона, **аппроксимация не обязана точно проходить через узлы**. Коэффициенты минимизируют сумму квадратов отклонений:

$$
\min_{c_0,a_k,b_k}\sum_i\bigl(T(x_i)-y_i\bigr)^2.
$$

Составляется матрица базиса со столбцами `1, cos(x), sin(x), ..., cos(rx), sin(rx)` и решается задача `A·c ≈ y` методом QR. В проекте QR строится модифицированным методом Грама — Шмидта **с повторной ортогонализацией**, после чего решается верхнетреугольная система `R·c = Qᵀ·y` обратным ходом.

Максимальное число гармоник определяется количеством узлов (`2r + 1 ≤ число узлов`) и ограничено константой `MAX_HARMONICS = 12`. Если матрица оказывается вырожденной, программа уменьшает число гармоник и повторяет подбор; в крайнем случае остаётся постоянная функция, равная среднему значению узлов. Такой режим полезен для приближения периодического поведения, но фиксированный период `2π` следует учитывать при выборе узлов.

**Реализация:** `TrigPolynomial.kt`, `TrigBasis.kt`, `LeastSquaresSolver.kt`.

### Натуральный кубический сплайн

Вместо одного многочлена высокой степени на каждом отрезке `[xᵢ, xᵢ₊₁]` строится отдельный кубический многочлен:

$$
S_i(x)=a_i+b_i(x-x_i)+c_i(x-x_i)^2+d_i(x-x_i)^3.
$$

Коэффициенты выбираются так, чтобы сплайн проходил через узлы, а значения первой и второй производных совпадали на внутренних стыках. Используются **естественные граничные условия**:

$$
S''(x_0)=S''(x_m)=0.
$$

Система для коэффициентов `cᵢ` трёхдиагональная и решается методом прогонки: сначала вычисляются прямые коэффициенты `α, β`, затем выполняется обратный ход. После этого находятся `aᵢ = yᵢ`, `bᵢ` и `dᵢ`. Для `m` отрезков построение занимает `O(m)` операций.

**Ограничение:** сплайн в приложении определён только между крайними узлами `[x₀, xₘ]`; экстраполяция за них не выполняется. При двух узлах получается линейная функция.

**Реализация:** `features/spline/Spline.kt`, `SplineSegment.kt`.

### Функция, заданная формулой

Можно ввести `f(x)` напрямую, например `sin(x) + x / 3` или `x^2`. Выражение разбирается библиотекой **mXparser**. Этот режим не использует узлы интерполяции. Для каждого независимого вычислителя формулы создаются собственные объекты переменной и выражения, чтобы корутинные задачи не разделяли изменяемое состояние парсера.

**Реализация:** `core/CurveDefinition.kt`.

## 2. Численное интегрирование

Интегрируется **текущая построенная функция**, независимо от того, каким методом она получена. Интервал `[a, b]` делится на `n` равных отрезков ширины `h = (b - a)/n`, где `1 ≤ n ≤ 20 000`. У всех методов одна сетка разбиения, что делает сравнение результатов осмысленным.

### Прямоугольники

Для `xᵢ = a + ih` применяются три правила:

| Метод | Формула приближения |
|---|---|
| Левые прямоугольники | `h · Σ f(xᵢ)`, `i = 0…n−1` |
| Средние прямоугольники | `h · Σ f((xᵢ+xᵢ₊₁)/2)`, `i = 0…n−1` |
| Правые прямоугольники | `h · Σ f(xᵢ₊₁)`, `i = 0…n−1` |

Для достаточно гладких функций левые и правые прямоугольники обычно имеют глобальную погрешность порядка `O(h)`, а средние — `O(h²)`. Это теоретические оценки при соответствующих условиях гладкости, а не гарантии для произвольной введённой формулы.

### Метод трапеций

На каждом элементарном отрезке график заменяется прямой между концами:

$$
I_n=\sum_{i=0}^{n-1}\frac{h}{2}\left(f(x_i)+f(x_{i+1})\right).
$$

Метод точен для линейной функции и обычно имеет глобальную погрешность `O(h²)` для дважды непрерывно дифференцируемой функции. **Метод Симпсона в приложении отсутствует.**

### Выборочные суммы Дарбу

Для разбиения теоретические суммы Дарбу имеют вид

$$
s(f,\mathcal P)=\sum_i m_i\,h,\qquad
S(f,\mathcal P)=\sum_i M_i\,h,
$$

где `mᵢ` — инфимум, а `Mᵢ` — супремум функции на `i`-м отрезке. В общем случае найти их точно численно невозможно, поэтому **реализация берёт 33 равномерные точки на каждом отрезке** (включая концы), а затем использует минимум и максимум этих выборок.

Таким образом, отображаемые «нижняя» и «верхняя» суммы — **выборочные приближения**, а не доказанные математические границы интеграла для произвольной функции. В интерфейсе также выводится разность между ними. Увеличение `n` уточняет разбиение, но не заменяет поиск истинных экстремумов.

**Реализация квадратур:** `core/NumericalIntegration.kt`.

### Выбор границ интеграла

- **Ручной режим:** используются введённые `a`, `b`.
- **«Интегрировать по всему X от…до»:** используются границы построения `x_min` и `x_max`; поля `a`, `b` становятся неактивными.
- **Сплайн с включённым переключателем:** берётся пересечение `[x_min, x_max]` с отрезком между крайними узлами. Например, `[-5, 5] ∩ [-3, 3] = [-3, 3]`. Если пересечение пусто, выводится ошибка.
- **Сплайн в ручном режиме:** `a`, `b` не меняются автоматически; выход за крайние узлы считается ошибкой.

Расчёт, подпись результата и графическая заливка используют одни и те же фактические границы. Значения функции на интервале должны быть конечными; недопустимые точки и переполнение вызывают сообщение об ошибке.

**Реализация:** `core/IntegrationBounds.kt`, `core/CurveDefinition.kt`.

## 3. Последовательное вычисление и корутины

В меню «Режим вычисления» доступны два варианта:

1. **Последовательно:** все `n` отрезков обрабатываются одной задачей на `Dispatchers.Default`.
2. **Корутины:** диапазон индексов разбиения делится между несколькими задачами `async(Dispatchers.Default)`. Число задач — не более `min(n, 8, число доступных процессоров)`; каждая считает свою частичную сумму, затем результаты объединяются через `awaitAll()`.

Используется **тот же метод интегрирования**: режим корутин меняет организацию расчёта, а не математическую формулу. При переключателе «Сравнить оба режима» приложение показывает времена, количество задач и абсолютную разницу результатов. Небольшие расхождения возможны из-за другого порядка сложения чисел `Double`.

Обе версии работают вне UI-потока; вычисление запускается после короткой задержки при изменении параметров, предыдущие задачи допускают отмену. Для небольшого `n` параллельная версия может оказаться медленнее из-за накладных расходов.

**Реализация:** `core/IntegrationRunner.kt`, `workspace/WorkspaceScreen.kt`.

## 4. График и управление

- **Узлы:** щелчок ЛКМ по графику или ввод координат; отдельные действия для удаления, очистки и восстановления демонстрационного набора. Максимум — 20 узлов.
- **Перемещение:** перетаскивание сдвигает видимую область; колесо мыши и кнопки `+`/`−` меняют масштаб; «Центр» сбрасывает положение и масштаб.
- **Оси:** автоматически подписываются числа с шагом вида `1`, `2` или `5` × `10ᵏ`, выбранным по текущему масштабу.
- **Разбиения:** прямоугольники и трапеции подсвечиваются на графике; для `n > 120` рисование разбиений отключается, чтобы не перегружать Canvas. Сам интеграл всё равно рассчитывается по всем `n` отрезкам.
- **Режим построения:** смена типа кривой не удаляет ранее добавленные узлы. Поле формулы показывается только в режиме `f(x)`.

**Реализация:** `core/Viewport.kt`, `core/AxisTicks.kt`, `workspace/UnifiedGraph.kt`, `GraphGrid.kt`, `GraphCurve.kt`, `GraphIntegration.kt`.

## 6. Проверка корректности

Команда `gradle test` запускает тесты, охватывающие:

- совпадение значений полиномов Лагранжа и Ньютона с узлами;
- построение постоянной тригонометрической аппроксимации;
- интегрирование линейных функций средними прямоугольниками и трапециями;
- вычисления для простых сплайнов, в том числе с двумя узлами;
- ограничение интервала интегрирования областью определения сплайна;
- выборочные суммы Дарбу для монотонной тестовой функции;
- согласованность последовательного и корутинного вычислений;
- шаг числовых делений и формат их подписей.

Тесты проверяют отдельные свойства реализации, но не гарантируют точности интегрирования для любых введённых функций и параметров.

## Обновление проекта

Скрипт `update-megakotl.sh` сначала распаковывает ZIP во временный каталог и проверяет `gradle compileKotlin`. Только после успешной компиляции он переносит старую папку в резервную копию и устанавливает новую. Пример для архива из `~/Downloads`:

```bash
unzip -p ~/Downloads/MegaKotl_docs.zip MegaKotl/update-megakotl.sh \
  | bash -s -- ~/Downloads/MegaKotl_docs.zip ~/kotl/MegaKotl
```

Чтобы установить новую версию **без автоматического запуска окна**, используйте тот же конвейер с `RUN_APP=0 bash -s --` вместо `bash -s --`.
